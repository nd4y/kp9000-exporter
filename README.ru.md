# kp9000-exporter

[🇬🇧 English](README.md) | 🇷🇺 **Русский**

Prometheus-экспортер для свитчей KeepLink KP-9000-6XHML-X2 — недорогих
веб-управляемых 2.5G/10G свитчей на Realtek с прошивкой `login.cgi`/`port.cgi`
(Hasivo и похожие ребренды, скорее всего, тоже подойдут).

У этих свитчей наружу торчит **только HTTP**: SNMP, telnet и SSH в прошивке
отсутствуют (проверено на V100.9.4 и V1.6), так что обычный путь через
`snmp_exporter` закрыт. Экспортер логинится в веб-морду и парсит три страницы —
`info.cgi`, `port.cgi`, `port.cgi?page=stats`.

Несколько свитчей опрашивает один процесс (`SWITCH_TARGETS`); каждая метрика
несёт метку `switch`. Только стандартная библиотека Python — зависимостей нет,
скрипт работает на голом `python:3.12-alpine` с одним bind-mount.

## Метрики

| Метрика                                              | Тип     | Описание                                       |
| ---------------------------------------------------- | ------- | ---------------------------------------------- |
| `kp9000_up`                                          | gauge   | скрейп веб-морды удался                        |
| `kp9000_scrape_duration_seconds`                     | gauge   | длительность скрейпа                           |
| `kp9000_device_info`                                 | gauge   | модель, MAC, версии прошивки/железа в метках   |
| `kp9000_port_enabled{port}`                          | gauge   | порт административно включён                   |
| `kp9000_port_link_up{port}`                          | gauge   | линк поднят                                    |
| `kp9000_port_speed_mbps{port}`                       | gauge   | согласованная скорость, Мбит/с (0 = нет линка) |
| `kp9000_port_flow_control{port}`                     | gauge   | flow control активен                           |
| `kp9000_port_{tx,rx}_{good,bad}_packets_total{port}` | counter | счётчики пакетов                               |

Счётчики у свитча 32-битные и переполняются примерно на 4.29 млрд пакетов —
`rate()`/`increase()` обрабатывают это как обычный counter reset, просто держите
интервал скрейпа разумно коротким (30–60 с).

Байтовых счётчиков и DDM-данных SFP-модулей (температура, оптическая мощность
и т.д.) прошивка не отдаёт никак — ни через веб, ни другим способом, поэтому
кроме перечисленного экспортировать нечего.

## Конфигурация (env)

| Переменная       | Дефолт        |                                                    |
| ---------------- | ------------- | -------------------------------------------------- |
| `SWITCH_TARGETS` | `192.168.0.3` | адреса свитчей через запятую (хост или `http://…`) |
| `SWITCH_USER`    | `admin`       | логин                                              |
| `SWITCH_PASS`    | `admin`       | пароль                                             |
| `LISTEN_PORT`    | `9835`        | порт `/metrics`                                    |
| `SWITCH_TIMEOUT` | `5`           | таймаут HTTP-запросов к свитчу, сек                |

## Запуск

```bash
docker compose up -d
curl http://localhost:9835/metrics
```

Или готовым образом:

```bash
docker run -d --name kp9000-exporter \
  -e SWITCH_TARGETS=192.168.0.3,192.168.0.4 \
  -p 9835:9835 \
  ghcr.io/nd4y/kp9000-exporter:latest
```

`/healthz` — дешёвый liveness-эндпойнт, который не трогает свитчи: healthcheck
контейнера направляйте туда, а не в `/metrics`.

## Нюансы

- Сессия в прошивке привязана к IP клиента и быстро протухает, поэтому экспортер
  логинится заново при каждом скрейпе. Побочный эффект: открытая в браузере с
  **другого** IP админка может иногда разлогиниваться — прошивка держит одну
  активную сессию.
- Авторизация — `admin=md5(username+password)` в cookie плюс POST в `login.cgi`;
  пароль ходит по сети нешифрованным MD5-хешем, HTTPS у свитча нет. Экспортер
  ничего не ухудшает — штатная веб-морда работает ровно так же.
- Прошивка V1.6 отдаёт кривой HTML (`</td align="center">`) — парсер сознательно
  к этому терпим.
